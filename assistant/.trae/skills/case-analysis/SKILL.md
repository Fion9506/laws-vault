# 会计处理案例分析（主应用）

产物仅供会计研究参考，须由财务人员复核，不代表官方意见。资料收录、标明来源或投诉处理声明均不代替转载授权；完整来源与范围见 `docs/SOURCES_AND_ACKNOWLEDGEMENTS.md`、`docs/REFERENCE_AND_RIGHTS.md`。

## 工作流（严格按序）

### Step 1 转录
把用户口语化输入转成结构化 JSON（先输出再继续）：

```json
{
  "业务描述": "…",
  "合同/条款要素": ["…"],
  "识别的会计问题": ["…"],
  "候选准则": ["CAS…"],
  "时间要素": {"业务时点": "…", "报告期": "…"},
  "口语→术语映射": {"…": "…"}
}
```

常用映射：「免费保养X年」→质保（CAS14 单项履约义务 vs CAS13 或有事项）；「政府补贴买设备」→与资产相关政府补助（CAS16）；「售后回租」→CAS21/CAS14；「送积分」→附额外购买选择权（CAS14）；「可能败诉赔偿」→预计负债（CAS13）；「可转债」→CAS22/37；「减值转回」→CAS8 禁止/CAS1 允许。

### Step 2 路由检索
- 只在候选准则对应文件内定向检索（`cas/NN.md` → `casi/` → `casc/NN__*` + `casq/NN__*` 三层）
- 检索词用术语映射结果，禁止拿原始口语直接搜
- 低置信才扩展全库；税法问题去 `tax/lawtext/content/`（按 front-matter title 检索）

### Step 3 时效过滤（as-of）
读命中文件 front-matter：`status` 六态 + `effective_date`。业务时点早于生效日或 status=尚未生效/已废止 → 剔除（例：2026 年报的 CAS30 用 cas/30.md 2014版，cas/30b.md 2027 才生效）。

### Step 4 输出（结构固定）

每条依据分别填写官方出处、实际采集来源和库内文件。`source_url` 是实际采集地址，指向 MaoDocs 时标注第三方镜像，不因 `org: 财政部` 将其冒充官方链接。只有实际核对过的官方地址才能填写为已核对的官方出处；缺失时写“未核对”，不得猜测URL。只有 `official_source_url` 标注、没有实际核对记录时，同样说明未核对。无文号或条号的指南/问答使用真实章节或问答定位，不编造。

`fetched_at` 只表示采集日期；历史 `checked_at` 可能也是抓取日，不表示官方核验。核验记录只填写实际执行的核验方式、结果和日期，未核验必须明示。

```
仅供会计研究参考，须人工复核，不代表官方意见。
```

## 红线

- 一切法规引用只准来自工作区文件；禁止网络搜索充当法规依据
- 检索不中 → 「未检索到现行依据」，禁止凭记忆背条文
- policy/ 公司办法仅「内部口径」，与准则两栏分层；会计/税务禁止互串依据
- casc/casq 作佐证层；实务观点不得作准则依据
- 意见书存 `OUTPUT/YYYYMMDD_主题.md`
